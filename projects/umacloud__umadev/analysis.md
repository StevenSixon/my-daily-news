## 它是什么
umadev 是一个 Rust 编写的编码代理，不自带模型，而是将 Claude Code、Codex 或 OpenCode 作为“大脑”，驱动连续的编码会话。它模拟一个由 8 个专家（产品经理、架构师、设计师、前后端、QA、安全、DevOps）加上 1 个协调员组成的真实开发团队，通过定义清晰的阶段（需求、架构、UI/UX、实施、质量门、交付）输出可运行的代码和审计证明。

## 为什么火
它解决了 AI 编码工具常见的“上手就写、缺设计、缺测试、无交付证据”问题，通过强制规范的工作流将临时对话变成可重复、可审计的构建过程。内置 459 个标准知识文件的双通道本地 RAG（BM25+向量）在每次工具调用时注入工程规范，且完全本地运行，无需额外 API 密钥。

## 技术栈
- 语言：Rust（单二进制）
- 分发：npm 做外壳，预编译二进制支持 macOS/ Linux/ Windows
- 知识检索：纯 Rust 实现的 BM25 + 本地嵌入模型（multilingual-e5-small, f16，通过 Candle）的混合检索，带 RRF 融合和 HyDE 查询扩展
- 记忆：自我进化的错误记忆和反思机制
- 依赖：需预先安装并已登录的 AI 编程 CLI（Claude Code、Codex 或 OpenCode 之一）

## 核心能力
- **多角色协作**：8 角色 + 协调员，通过产物文件和结构化判别协同，不相互聊天
- **完整交付流**：从意图判断、需求澄清、调研、PRD/架构/UI/UX 文档、执行计划、分步实施、质量门到交付包
- **治理》**：基于 UMADEV_HOST_SPEC_V1 的 112 条规则，代码审核强制标准
- **本地离线 RAG**：无网络、无 API 密钥，毫秒级检索内置标准
- **自适应规模**：小修改只走轻量流程，大项目调度全团队
- **实现隔离分支**：在专用 `umadev/<slug>` 分支上工作，不影响当前分支

## 适用场景
- 想要将 AI 编码纳入标准化流程的团队
- 从零构建完整可交付项目的开发者（如“做个带 Postgres 后端的待办应用”）
- 需要产出审计轨迹（需求映射、合规报告）的商业项目
- 对网络无依赖、完全本地运行知识库敏感的离线环境

## 同类对比
- 与直接使用 Claude Code 等 CLI 相比：umadev 提供团队流程、治理和交付包装
- 与 Cursor、Copilot 相比：它更像一个构建代理而非编辑器插件，并强调交付物
- 与 Devin、OpenHands 等全自动代理相比：umadev 不自带模型，复用已有登录，更轻量、本地化，且治理规则可审计
