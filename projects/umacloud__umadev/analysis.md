## 它是什么
umaDev 是一个 Rust 编写的“编码团队代理”，它本身不拥有模型，而是驱动你已经安装并登录的 AI 编码 CLI（Claude Code、Codex 或 OpenCode）像一个真正的开发团队那样工作。它内置了八个专家角色（产品经理、架构师、UI/UX 设计师、前后端工程师、QA、安全工程师、DevOps），外加一个协调者，共同完成从需求分析到交付证明的全流程。

## 为什么火
当前 AI 编码工具普遍存在“一上来就写代码、缺乏架构设计、前后端不匹配、生成结果不可审计”等问题。umaDev 通过强流程治理和团队角色分配，将一次性编码转化为可重复、可审计、带交付证明的软件工程过程。它利用了用户已有的 CLI 工具和模型配置，不引入额外 API 依赖，且知识库完全本地化，无需联网，这在注重隐私和治理的工程团队中极具吸引力。

## 技术栈
- 语言：Rust（编译为单二进制）
- 分发：npm 作为安装壳，预编译二进制支持 macOS (Apple Silicon/Intel)、Linux (x86_64/ARM64)、Windows (x86_64)
- 知识检索：纯 Rust BM25 + 本地向量模型（multilingual-e5-small，通过 candle 推理），混合检索，支持 HyDE 查询扩展，完全离线
- 嵌入式模型：首次运行时自动下载到 ~/.umadev/embed-model，无网络时回退到 BM25
- 工程文档：遵循 UMADEV_HOST_SPEC_V1 规范，含约 459 个知识文件

## 核心能力
- **团队式工作流**：根据任务复杂度自动路由，调度八角色协同，每个角色有出产物和签字机制
- **规划与 Checklist**：生成依赖计划（plan.json）并可视化为实时清单，可手动操控
- **质量门与交付证明**：包括构建、测试、lint、契约检查、运行时探测、治理扫描，最终产出评分卡和证明包
- **本地优先 RAG**：自带工程标准知识库，结合用户代码地图，为每一步提供注入的上下文
- **无模型锁定**：驱动已有的 CLI，用户可自由选择底层模型和配置
- **聊天即构建**：在 TUI 中发出的构建请求享受与命令行 `umadev run` 同等的完整治理过程

## 适用场景
- 单人开发者希望用 AI 生成可交付的完整项目，而非零散的代码片段
- 团队需要规范化 AI 编码流程，确保产出符合内部工程标准
- 对数据隐私敏感的环境，要求所有处理本地完成
- 已有 Claude Code / Codex / OpenCode 的使用者，希望升级为“团队级”交付体验

## 同类对比
与直接使用 Claude Code、Codex 等 CLI 相比，umaDev 提供了流程化治理、多角色协作和交付证明。与类似的全自动编程代理（如 GPT-Engineer、MetaGPT）相比，umaDev 不重新实现模型调用，而是利用用户已有的工具和认证，更轻量且易于集成；其本地双通道 RAG 和严格的工程化治理也是差异化亮点。但 umaDev 目前主要依赖用户已有 CLI，灵活性可能受限于这些工具的接口。
