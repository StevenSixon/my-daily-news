## 它是什么
umadev 是一个 **编码代理**，它像真实开发团队一样工作，驱动你已经安装并登录的 AI 编码 CLI（Claude Code、Codex 或 OpenCode）作为一个连续会话，自己不带模型。它模拟八个专业角色（PM、架构师、UI/UX、前端、后端、QA、安全、DevOps）和一个技术负责人协调者，将你的需求转化为规划、研究、PRD/架构/UI设计、分步实现、质量关卡和交付证明。它是一个 Rust 编写的二进制文件，通过 npm 分发，完全离线可用，包括本地向量检索（多语言 e5-small 模型，无网络、无 API 密钥）。

## 为什么火
（目前 Star 223，兴起中）它在 AI 编码工具之上注入了一套完整的工程流程，解决了裸用 CLI 时立刻写代码、前后端脱节、UI 千篇一律、遗留占位符、缺乏交付物的问题。对期望 AI 生成可维护、可交付项目的开发者，它把"你随便说，我直接写"变成了"先明确规格，再设计架构，分步实现并验证"。本地 RAG 内置 459 个工程标准文件，能将团队规范自动注入每一次交互，而不泄露代码到云。

## 技术栈
- **Rust**：核心逻辑、规划器、RAG 引擎、TUI 均用 Rust 实现，单二进制，启动快
- **混合检索**：纯 Rust 的 BM25 + candle 本地向量模型（multilingual-e5-small），HyDE 查询扩展，RRF 融合，离线运行
- **集成层**：通过终端命令调用用户安装的 Claude Code / Codex / OpenCode CLI，无侵入
- **知识库**：编译进二进制的工程规范，支持动态注入用户知识
- **分支隔离**：每次构建在独立的 `umadev/<slug>` 分支进行，不影响工作目录

## 核心能力
- **团队模拟**：协调者路由请求，调度 8 个角色，通过工件文件与结构化裁决协作，而非聊天
- **全流程驱动**：需求→研究→PRD/架构/UI/UX→执行计划（plan.json）→前端预览→后端→质量门→交付证明包
- **本地 RAG**：每次模型调用都检索相关工程标准（商业级规范），无网络、零配置，确保代码符合团队规则
- **质量与治理**：基于 UMADEV_HOST_SPEC_V1 的 32 条规范约 112 条治理规则，包含测试、Lint、契约检查、运行时探针、安全扫描等
- **自适应规模**：小改动只触发轻量检查，完整项目召集团队全部角色
- **目标模式 /goal**：持续迭代直到目标达成，而非一次生成

## 适用场景
- 你已经有 Claude Code / Codex 等 CLI，但希望每次构建都有规划、架构、评审
- 个人产品或团队内部工具需要保持工程一致性，而不仅仅是"看起来能跑"
- 必须离线环境或高度关注数据隐私，不希望代码片段被发送到 API 进行嵌入（默认本地模型）
- 需要交付证据（PRD、架构图、测试报告、合规审查单）给客户或团队审核

## 同类对比
- **GPT Pilot**：也模拟角色和流程，但基于自己的 LLM API 调用，非本地 RAG，且需要联网
- **Aider / Claude Code 原生**：直接交互，无规划层和治理层，缺乏多角色协调与交付物
- **OpenHands / SWE-agent**：面向代码仓库的自主代理，但通常没有从需求到交付的全生命周期流程，也没有内置工程规范检索
- **umadev 的差异在于**：它不发明新的模型调用方式，而是赋能用户已有的 CLI，用一套可验证的流程和本地知识库营造"虚拟团队"，同时保持极低的网络依赖和隐私风险
