## 它是什么
Cindy 是一个开源、开箱即用的 AI 代理客户端，可在本地机器上运行，直接使用用户的真实文件和已登录应用。它将多种执行后端（称为 harness）、模型和工具整合到一个统一的代理中，首个支持的 harness 为 **Claude Code** 和 **Codex**，原生 harness 也在开发中。项目采用 pnpm monorepo 管理，包含 Electron 桌面端、React Native 移动端及共享包，官方提供 Windows/macOS/Linux/iOS/Android 安装包，并区分全球版与中国大陆版。

## 为什么火
在 AI 编码助手泛滥的当下，Cindy 解决了三个核心痛点：1）**订阅过载** – 用户可以复用自己已付费的 Claude Code 或 Codex 计划，无需额外付费；2）**隐私与安全** – 代理完全本地运行，文件与聊天内容不上传云端（使用云服务时仅同步必要元数据）；3）**开放性** – 源码以 Apache-2.0 开放，允许审计、分叉和扩展，且通过记忆、技能和插件系统实现深度定制，而同类产品多为黑盒或仅提供有限 API。

## 技术栈
- 客户端：Electron（桌面）、Expo / React Native（移动）
- 语言：TypeScript
- 构建工具：Node.js 22.x、pnpm 10.x、Git LFS
- 核心协议：`cindy-protocol`（与后端服务的线路协议，作为 git 子模块）
- 模型接入：支持 Claude Code、Codex、用户自定义 API Key 或本地模型，harness 与模型可混用并在任务中途切换
- 工程规范：DCO 签名贡献、CI 流程、独立的设计系统文档（DESIGN.md）

## 核心能力
- **跨 harness 编排**：同一任务可在不同 harness×模型组合上规划、并行执行和审查，工作空间、记忆、技能和工具保持连续。
- **记忆与技能**：代理可被纠正一次后永久记住做法；可定义工作流并复用，团队共享功能开发中。
- **自动化与 MCP**：支持定时任务，以及通过 MCP 接入企业内部工具和系统。
- **多端控制**：代理能驱动浏览器、电脑和手机，并从 IM 和日程中获取任务。
- **双模式运行**：
  - **托管服务**：登录 Cindy 云账户，使用完整服务，用量透明扣费。
  - **本地模式**：无账号要求，仅使用本地代理，但服务端功能不可用。
- **插件市场（开发中）**：可重塑功能、UI 和交互，通过开放市场分享。

## 适用场景
- 已有 Claude Code/Codex 订阅的开发者，希望用一个客户端统一管理多模型任务，避免切换工具。
- 重视隐私、需处理敏感数据的团队，要求 AI 代理完全在本地执行。
- 希望深度定制 AI 工作流、记忆和技能的企业或极客用户。
- 跨平台（桌面+移动）协同的自动化场景，例如让代理同时在电脑和手机上执行操作。

## 同类对比
| 工具 | 定位 | 优势 | 弱点 |
|------|------|------|------|
| **Cindy** | 开源 AI 代理客户端 | 复用已有订阅、本地运行、记忆与技能系统、多 harness 混用 | 服务端闭源，插件市场未上线 |
| **Claude Code** | 编码 AI 助手 | 官方维护，深度集成 Anrhopic 模型 | 单一模型，不能混用其他后端 |
| **OpenCode** | 开源编码代理 | 简单轻量，支持多种模型 API | 无记忆/技能系统，无移动端 |
| **Copilot** | 商业编码助手 | 生态完善，IDE 深度集成 | 闭源，依赖特定订阅，无法自托管 |
