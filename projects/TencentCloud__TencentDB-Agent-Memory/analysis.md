## 它是什么
TencentDB Agent Memory 是一个专为 AI Agent 设计的本地记忆系统，采用 4 层渐进流水线（L0 对话 → L1 原子事实 → L2 场景 → L3 人设）实现长期记忆，同时提供基于 Mermaid 图表的符号短期记忆来应对长任务中的上下文膨胀。核心卖点：**零外部 API 依赖**，所有记忆处理在本地完成，可以集成到 OpenClaw 或 Hermes 框架中。

## 为什么火
- 解决了两大长久痛点：**长会话中工具日志挤占上下文**（token 消耗降低最高 61.38%）、**跨会话记忆丢失**（PersonaMem 准确率从 48% 提升至 76%）。
- 完全本地运行，无需云服务，保护数据隐私，满足自托管需求。
- 与主流 Agent 框架（OpenClaw、Hermes）原生集成，开箱即用。

## 技术栈
- 语言：TypeScript
- 存储：本地 SQLite + sqlite-vec 向量索引
- 嵌入模型：支持 OpenAI 兼容端点，默认使用腾讯云 LKE，但核心记忆管道不依赖外部 API
- 集成：OpenClaw 插件、Hermes provider
- 要求：Node.js ≥22.16，OpenClaw ≥2026.3.13

## 核心能力
1. **分层长期记忆**：从对话中逐步提炼原子事实 → 场景块 → 用户人设，上层作为轻量索引，下层保存完整证据，实现“渐进披露”和“可恢复压缩”。
2. **符号短期记忆**：将冗长的工具输出压缩成 Mermaid 关系图，Agent 仅需关注图形节点，需要细节时通过 `node_id` 回溯原始日志，既省 token 又保留可溯源性。
3. **多框架适配**：同时支持 OpenClaw（作为插件）和 Hermes（通过 Gateway 或 Docker）。
4. **智能特性（v0.3.6）**：上下文预算控制（限制每记忆字符数）、提示词按用户语言自适应、Gateway 鉴权与 CORS 白名单、文件名自动归一化等。

## 适用场景
- 需要长期个人化的 Agent（如编程助手记住用户偏好、项目惯例）
- 长任务执行（如 SWE-bench 持续 50 步的任务流，记忆不会丢失中间状态）
- 隐私敏感场景：完全本地运行，数据不出机器
- 自托管 Agent 记忆层，替代基于云 API 的记忆方案

## 同类对比
- 相较于 **Mem0** 等扁平向量记忆，本系统坚持分层存放，不仅存储事实，还自动生成场景和人设，使召回更具结构性和可解释性。
- **短期记忆方面**，符号化压缩比传统的自动摘要或全量历史更具信息密度和可验证性，避免了不可逆的信息丢失。
