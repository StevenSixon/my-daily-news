## 它是什么
Gas Town 是一个用 Go 编写的多 AI 代理工作空间管理器。它通过 Git 工作树（Hooks）持久化每个代理的状态，支持 Claude Code、GitHub Copilot、Codex 等代理协同工作。项目引入了一整套隐喻：市长（Mayor）作为主协调器、钻井工（Polecats）作为工作代理、护航队（Convoys）打包任务、炼油厂（Refinery）处理合并队列，以及三级看门狗来保障代理健康。

## 为什么火
当团队同时运行多个 AI 编码代理时，上下文容易丢失，手动协调极易混乱。Gas Town 让代理像常规开发工具一样被管理，状态被 Git 化存储，即使代理崩溃或重启也能无缝恢复。它宣称可扩展至 20-30 个代理，并提供了合并队列、公式工作流、会话发现等高级特性，吸引了很多重度 AI 编码用户的关注。

## 技术栈
- 语言：Go 1.25+，核心二进制 `gt`
- 存储：Git worktree（Hooks），Dolt（Wasteland 联邦、护航队数据库），beads（issue 跟踪）
- 运行时依赖：Git 2.25+，Dolt 2.0.7+，beads（bd）0.55.4+，sqlite3，tmux 3.0（推荐）
- 支持的 AI 代理运行时：Claude Code CLI、Codex CLI、GitHub Copilot CLI，并可配置自定义命令
- 部署：Homebrew、npm、源码编译，也支持 Docker Compose

## 核心能力
- **持久化与交接**：每个代理有独立身份，通过 Hooks（Git 工作树）存储工作状态，重启不丢失
- **任务编排**：Convoys 将多个 Bead（issue）打包，自动分配，支持人工指派
- **代理生命周期**：三级看门狗（Witness、Deacon、Dogs）监控代理是否卡死、清理遗留 TMUX 会话、检测 API 限额等问题
- **合并队列（Refinery）**：Bors 风格二分合并队列，自动验证代理提交后合并到主分支
- **公式工作流**：TOML 定义可复现步骤，支持变量和依赖关系，可生成分子（Molecules）进行追踪
- **会话发现（Seance）**：代理可查询前任会话日志，获取历史决策上下文
- **联邦协作（Wasteland）**：通过 DoltHub 连接多个 Gas Town，交换任务、赚取信誉
- **调度器**：限制并发代理数，避免 API 速率耗尽
- **轻量模式**：无需 tmux 即可手动运行单个代理，仅状态跟踪

## 适用场景
- 团队同时运行多个 AI 辅助编码代理，需要状态不丢、协调有序
- 大型代码库中执行多步重构或并行特性开发，希望自动化合并验证
- 利用代号“废土”进行跨组织、跨仓库的分布式 AI 编码协作
- 偏好本地化、自托管方案，不依赖外部云服务的用户

## 同类对比
- 相比 CrewAI、AutoGen 等通用 LLM 代理框架，Gas Town 更专注于代码仓库的实际操作，深度集成 Git 和开发工作流
- 与 LangChain Agent 等对比：不直接调用模型，而是管理已有的 AI 编码 CLI 实例
- 在合并队列方面类似 Bors/homu，但被包裹进 AI 代理工作流
- 目前是特定场景下的创新工具，尚无直接竞品
