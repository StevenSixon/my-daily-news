## 它是什么
herdr 是一个终端多路复用器，专门为管理和观察多个AI编码Agent（如 Claude Code、Codex 等）设计。它提供类似 tmux 的窗格、会话持久化、分离/重连，但增加了一层“Agent意识”：能直接展示Agent的实时输出、状态（阻塞/工作/完成），并允许Agent通过内置 Socket API 自行拆分窗格、读取输出、等待其他Agent。

## 为什么火
14231个Star（2026-03-27 创建后3个月），冲上趋势榜，因为它抓住了开发者在“AI Agent并发”场景下的痛点：当你需要同时运行多个AI编码Agent协同完成一个复杂任务时，传统的多终端窗口或 tmux 缺乏对 Agent 状态的感知和 API 接口；herdr 则让 Agent 成为一等公民，可以互相“看到”并协同，且脱离终端后继续运行，重连即可恢复上下文。

## 技术栈
- 语言：Rust
- 单二进制，无 Electron 依赖
- 提供 Homebrew、脚本安装
- 双许可证：AGPL-3.0 + 商业授权

## 核心能力
- **Agent多路复用**：将多个编码Agent的运行窗口并排显示，实时查看阻塞/工作/完成状态。
- **会话持久化**：`ctrl+b q` 分离，`herdr` 重连，支持SSH远程恢复。
- **Agent可编程接口**：纯Socket API，Agent可借此创建窗格、读取输出、等待其他Agent，即“Agent也能使用herdr”。
- **混合输入模型**：键盘（tmux风格前缀键）和鼠标（点击、拖拽、拆分）均为一级操作，无需切换模式。
- **插件系统**：可扩展窗格和工作流（存在插件市场）。
- **头less渲染**：可运行无界面渲染流，且能跳过可见URL扫描以降低重绘负载。

## 适用场景
- 同时管理多个AI编码Agent的协作任务（如一个Agent写后端，另一个写前端，第三个做测试）。
- 长时间运行的Agent任务，需要断开终端后继续执行并随时查看结果。
- 需要Agent之间进行同步/等待的复杂流水线。
- 在远程服务器上部署Agent，通过herdr持久化会话并远程重连。

## 同类对比
与 tmux 相比，herdr 引入了“Agent窗口”概念，原生展示Agent运行状态和输出，并提供Agent可调用的API层；而 tmux 只提供通用窗格，无Agent专有支持和程序化接口。与一些Agent编排框架（如自定义脚本+tmux）相比，herdr 更一体化，开箱即用，且性能由Rust保证。与基于Web的多Agent面板（如LangSmith Studio等）相比，herdr完全运行在终端，极轻量，无浏览器依赖。
